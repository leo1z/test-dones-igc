1 Mapa de Arquitectura y Decisiones Técnicas

🔍 Visión General de la Aplicación

La Web App Test de Dones IGC (v3.0.0) es una plataforma interactiva de evaluación espiritual diseñada para la Iglesia Gran Comisión Tegucigalpa. Permite a los miembros completar un test de 76 situaciones distribuidas en 10 partes temáticas para calcular su nivel de afinidad respecto a 15 dones espirituales. Cuenta con un sistema de puntuación determinista en escala de 1 a 3, un slideover de consulta rápida de dones, una encuesta de evaluación de experiencia y un Panel de Administración autónomo con análisis geográfico en mapa vectorial GeoJSON de Honduras y gráficos estadísticos avanzados de Apache ECharts.

💡 Analogías del Mundo Real para la Tecnología Utilizada:
  • Frontend (HTML/CSS/JS Vanilla): Es como la estructura física de un edificio (bloques, pintura y puertas). No usa armazones pesados externos (React/Next.js), por lo que se carga de forma instantánea al abrir.
  • Backend Service (Supabase REST API):** Es como un archivador electrónico remoto en la nube con un mensajero automático. Guarda los registros finales de cada test y atiende al administrador sin necesidad de mantener un servidor encendido pagando rentas caras.
  • Data Visualization (Apache ECharts + GeoJSON):** Es como un mapa táctico con luces LED de colores. Toma las ciudades seleccionadas en Honduras y enciende pines pulsantes y colores por departamento automáticamente.
  • Motor de Cálculo (`score-engine.js`):** Es una calculadora científica blindada. Recibe las 76 respuestas y entrega los 3 dones principales (Top 3) sin alterar nunca los resultados.

⚖️ Decisiones Clave de Ingeniería y Ventajas

1. JS Vanilla vs React/Next.js

Decisión: No usar librerías de UI pesadas.
Ventaja: Carga ultra-rápida (< 0.3s) en cualquier teléfono celular o conexión 3G en Honduras sin necesidad de un proceso de compilación complejo.

2. Persistencia Local + Supabase Asíncrono

Decisión: Guardar primero en localStorage del navegador.
Ventaja: Si el usuario se queda sin internet a mitad del test, sus respuestas están protegidas. Al reconectarse o enviar, se sincroniza con Supabase.

2 El Backend y Flujo de Datos (Cómo pedir cambios)

🔄 Ciclo de Vida de una Acción (Paso a Paso)

1

Selección de Respuesta por el Usuario

El usuario presiona una píldora (1: Rara vez, 2: A veces, 3: Frecuentemente). Se ejecuta handlePillClick() en app.js, que guarda el valor en memoria y actualiza localStorage.

2

Cálculo de Afinidad de Dones

Al completar la Parte 10 y hacer clic en "Finalizar Test", se invoca runFullCalculation() en score-engine.js. Suma los puntos por don y calcula el porcentaje exacto sobre la puntuación máxima posible.

3

Sincronización con Supabase Remote

finishTest() envía el objeto final a submitResult() en supabase-client.js, insertando la fila en la tabla dones_igc.results de Supabase y guardando el UUID de entrega devuelto.

4

Reinicio Limpio (Si aplica)

Si el usuario presiona "Reiniciar Test", deleteSubmission(submissionId) elimina la entrega remota en Supabase para evitar métricas duplicadas en el panel admin antes de borrar la memoria local.

📖 Diccionario del Backend Explicado para Principiantes

Término Explicación Simple Ejemplo en este Proyecto
REST API El protocolo de mensajería estándar para pedir o enviar datos a la base de datos remota mediante URLs. Llamadas HTTP a https://vmlbrjzsuceizrwqryjf.supabase.co/rest/v1/results.
Upsert / Insert Insertar un nuevo registro o actualizar uno existente si ya se conoce su identificador único (ID). supabase.from('results').upsert(payload) en supabase-client.js.
LocalStorage La pequeña base de datos interna dentro del navegador web del celular/computadora del usuario. Clave dones_igc_answers para guardar las 76 respuestas localmente.
RLS (Row Level Security) Las reglas de seguridad que determinan qué usuarios pueden leer o borrar filas de la base de datos. Permite a la aplicación guardar encuestas y al admin consultar métricas.
